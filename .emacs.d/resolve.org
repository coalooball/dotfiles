#+startup: overview

* Vertico error when opening a directory with Dired

** Symptoms

After running ~M-x dired~, Vertico repeatedly produced backtraces while displaying directory candidates. The key error was:

#+begin_example
Vertico detected an error:
  vertico--debug((wrong-number-of-arguments (1 . 1) 3))
  seconds-to-string(... expanded abbrev)
  marginalia--time-relative(...)
  marginalia--annotate-local-file("opt/")
  marginalia-annotate-file("opt/")
  vertico--affixate(...)
#+end_example

** Cause

The problem was not in Dired or Vertico, but in incorrect Marginalia bytecode generated during a package update:

- The ~seconds-to-string~ built into Emacs 30.2 accepts only one argument.
- Marginalia needs a compatibility implementation that supports extra arguments via Compat.
- Marginalia's source uses the correct ~compat-call~, but the generated ~marginalia.elc~
  incorrectly called the Emacs built-in directly and passed three arguments.
- This produced ~wrong-number-of-arguments (1 . 1) 3~.

This can happen when an old version of Compat is loaded in the same Emacs session before packages are upgraded. Simply updating the package does not necessarily regenerate correct bytecode.

** Recommended fix

Run the following in Emacs:

#+begin_example
M-x package-recompile RET marginalia RET
#+end_example

Then fully quit and restart Emacs. If you use the Emacs daemon, restart the daemon as well, not just the current frame.

After restarting, run the following again:

#+begin_example
M-x dired
#+end_example

Directory candidates should display normally, with no further Vertico backtrace.

** Fix without restarting

After recompiling, you can try reloading Marginalia immediately:

#+begin_src emacs-lisp
(progn
  (package-recompile 'marginalia)
  (load (locate-library "marginalia") nil 'nomessage))
#+end_src

If the problem persists, fully restart Emacs.

** Temporary workaround

Temporarily disabling Marginalia annotations keeps Dired and Vertico usable:

#+begin_src emacs-lisp
(marginalia-mode -1)
#+end_src

This only hides the extra information on completion candidates; it does not fix the bad bytecode.

** Verifying Compat

The following expression should return ~"1h"~ instead of raising an argument-count error:

#+begin_src emacs-lisp
(compat-call seconds-to-string 3600 'expanded 'abbrev)
#+end_src

If it still fails after recompiling Marginalia, recompile Compat and Marginalia in order, then restart and test again:

#+begin_example
M-x package-recompile RET compat RET
M-x package-recompile RET marginalia RET
#+end_example
